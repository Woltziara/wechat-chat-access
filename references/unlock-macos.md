# macOS 密钥接入恢复

只在现有密钥不能读取当前目标库时使用。该流程会中断微信，不能藏在doctor/read/search内自动触发。复用本次任务已有的退出重开微信授权；没有该授权时先完成准备，再交用户决定真正新增的中断。Mac不重启、SIP保持开启、原版微信不重签。

## 先分清失败层

1. 路径或账号错误：修正本机config，不抓钥。
2. 密钥缺失、salt变化或数据库页认证失败：进入本页。
3. 私有FTS分词器或字段解码失败：修读取器；不能误诊成需要再次提权/关闭SIP。
4. 原版hardened进程连接失败：普通/root均可能被系统拒绝；这不是“解密算法试过失败”。采用已验证的临时副本路线。

## 做好准备，再短时中断微信

1. 读取当前原版App的版本/build、签名、进程与本机数据路径。当前已验证4.1.13/build269602；新版本需重新核查实际行为。
2. **先核验系统管理员授权能完成，再退出微信**，避免停用微信后才长时间等授权。使用宿主正常的系统授权机制；密码只输入系统认证窗口，不存入Keychain、配置、日志或聊天。工具拒绝操作SecurityAgent时交用户亲自完成，不换UI工具绕过。
3. 用当前用户创建独占临时运行目录，0700。管理员子进程曾因TCC不能从Documents启动venv；必要时把采集脚本及Frida运行环境放到新建的 `/private/tmp/` 目录。不要硬编码上次临时目录。
4. 采集依赖为 `frida==17.18.0`；校验器只用标准库HMAC。可在私有运行环境安装，或先执行 `setup_runtime.py --with-capture`。不要复制聊天或密钥进入Skill。
5. 在本机私有状态目录创建原微信的独立副本。仅对副本执行 `codesign --force --deep --sign - <副本>`，验证副本签名、原版腾讯签名仍保持不变。不能顺手移除全局安全保护或修改原App。
6. 正常退出微信；不要自动升级成kill -9。确认进程关闭后，对当前账号db_storage及其WAL/SHM、账号config和相关登录配置留恢复副本，核对校验和。不要复制其他账号，不把活跃主库单独复制当成一致备份。后续不能自动用这份旧备份覆盖新消息。
7. 准备密钥验证清单（只含加密首页，不含密钥）：

```bash
"$PY" "$SKILL_DIR/scripts/prepare_inventory.py" --db-root "$DB_ROOT" --out "$ATTEMPT_DIR/inventory.json"
```

## 启动副本并取钥

1. 用**普通用户身份**启动临时副本，不能以root运行微信。根据真实可用的本机启动方式选择技术路线，使用明确副本路径；相同bundle id可能误定位到原版。
2. 启动调用报超时不等于没启动。读取真实PID及可执行文件路径，确认属于副本，再调用管理员采集器。不要盲目再开多个实例。
3. 优先采用“普通启动副本 + 管理员连接PID”，这是本机成功路径。不要默认用Frida普通用户 `--spawn`；该路径曾出现暂停后恢复失败，且不比已验证路径可靠。
4. 管理员子进程执行（各变量先由现场解析，切勿把key放入参数）：

```bash
"$CAPTURE_PY" "$ATTEMPT_DIR/capture_validated_keys.py"   --pid "$SHADOW_PID"   --inventory "$ATTEMPT_DIR/inventory.json"   --out "$ATTEMPT_DIR/validated-keys.json"   --status-file "$ATTEMPT_DIR/status.json"   --timeout 240 --quiet 180
```

将本Skill的 `capture_validated_keys.py` 与 `capture_crypto.js` 一起放入上述私有运行目录。参数可以按实际登录等待缩短；保持有界，不无限等待。初次可能需用户确认微信登录/数据访问，这属于登录配合，不是用UI读取聊天。

5. 读取状态文件中的stage/计数，区分授权未开始、连接成功、hook已就绪和认证覆盖。`hook_ready=false`或matched=0不能算成功。文件里没有key/salt/消息，不要改成输出候选值。
6. 采集器仅持久化通过目标DB首页HMAC的key，原子写0600，并按私有父目录归还普通用户所有权。退出码0表示该清单全覆盖；2表示部分覆盖且可能已有有效key，不能一律当“取钥失败”；1表示失败。管理员启动器可能把非零退出变成统一报错，仍应读取不含秘密的状态与实际密钥文件存在性。
7. 验证新key后再原子替换本机规范密钥文件；保存已有仍有效的项，不能拿另一账号key合并。不能把命中数量、文件存在或README的支持声明当成消息可读证据。

## 读回、恢复、收尾

- 先用新key实际只读打开所需库，再执行常规会话完整检查。区分旧迁移辅助库缺key与常规消息库缺key；按真实范围报告。
- 正常关闭任务副本并重新打开原版微信；如果现场已是原版在运行，不要再中断它。根据真实可执行文件路径判断，不复用旧PID。
- 原版微信运行后，用同一组key复测常规消息、WAL新记录和小样本查询时延。至此才能说“日常读取不依赖临时副本”。
- 注销任务副本的LaunchServices注册（若曾注册），恢复原版注册；确认副本无进程使用后清理任务创建的副本。原用户数据不回滚。
- key只在 `~/Library/Application Support/CodexWeChatRead/` 的私有文件保留一份，删除工作区/临时目录中的重复key；代码、说明、日志都不能包含真实key。
- 若授权/登录/启动失败，先恢复原版微信运行再交付明确阻点，不能让用户长期停在不可用的副本。

## 不沿用的路径

不要直接运行第三方一键bootstrap/全库export脚本：本次发现过保存管理员密码、日志输出raw key、忽略WAL、失败仍返回0、漏未知联系人表等行为。借用方法时核查当前源码和本机结果。参考 [wxkey临时副本方法](https://github.com/r266-tech/wxkey) 与 [CommonCrypto拦截方法](https://github.com/TimFang4162/wechat4-macos-frida-export)，不自动更新或轮询这些仓库。
